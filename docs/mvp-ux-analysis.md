# Asset Passport MVP UX 분석 보고서

> 상태: 보관 문서. 이 문서는 2026-07-31의 Release Gate 방향을 분석한 기록이다. 현재 AssetOps MVP의 기준은 [asset-passport-assetops-spec.md](asset-passport-assetops-spec.md)와 상태 기반 사용자 여정이다.

작성일: 2026-07-31  
대상: `https://redsunjin.github.io/assetpass/mvp/`

## 결론

**Manager control room과 Release workflow는 같은 화면의 동급 콘텐츠가 아니다.**

- Manager control room은 운영자가 지갑, 역할, AI 공급자, 에이전트를 **설정·관리**하는 곳이다.
- Release workflow는 제품이 어떤 원리로 움직이는지 알려 주는 **설명·안내**다.

따라서 둘을 한 페이지에 크게 병렬 배치하면 사용자는 “지금 공시를 처리해야 하는가, 시스템을 설정해야 하는가, 제품 설명을 읽어야 하는가”를 동시에 판단해야 한다. 이는 Release Gate가 해결하려는 문제와 반대다. 이 제품의 첫 화면은 오직 **‘현재 막힌 공시와 다음 책임 행동’**에 집중해야 한다.

## 현재 MVP의 역할별 구조

| 사용자 | 필요한 답 | 적합한 화면 |
| --- | --- | --- |
| 발행자·운영자 | 지금 무엇이 막혔고 누구에게 무엇을 요청해야 하는가 | 운영 화면 |
| 검토자 | 어떤 근거를 확인하고 어떤 지갑 행동을 해야 하는가 | 승인 화면 |
| 관리자 | 어떤 지갑·AI 공급자·에이전트가 연결되어 있는가 | 설정 화면 |
| 파트너·검증자 | 받은 파일과 공개 이력이 일치하는가 | 공개 검증 화면 |

현재 MVP는 운영 화면과 설정 화면을 탭으로 분리했다. 이는 올바른 첫 단계다. 다만 Release workflow의 상세 설명은 아직 운영자의 첫 업무 흐름에 비해 비중이 크다.

## 화면별 진단

### 1. 운영 화면

좋은 점:

- 첫 화면에 `공시 차단`, 차단 이유, 해결할 항목 수가 보인다.
- `검토자 승인으로 이동`과 `AI 근거 보기`가 다음 행동을 직접 가리킨다.
- 가상 자산 사례를 바꾸면 AI 판단과 상태가 함께 바뀐다.

남은 문제:

- 운영자는 제품의 작동 원리보다 현재 사건을 먼저 처리해야 한다. 상세 Release workflow는 첫 업무 화면의 집중도를 낮춘다.
- 사례 목록은 데모에는 유용하지만, 운영 제품이라면 ‘가장 긴급한 1건’이 먼저 잡혀야 한다.
- ‘검토자 승인으로 이동’은 현재 서명 미리보기로 이어진다. 테스트넷 배포 뒤에는 실제 승인 트랜잭션, 성공·실패 상태, Explorer 링크까지 한 흐름으로 이어져야 한다.

### 2. 설정 화면

좋은 점:

- 지갑·역할, AI 공급자, 에이전트 책임을 한곳에 모았다.
- 로컬 Ollama와 HTTPS 보안 릴레이를 공급자 프로필로 등록하고 연결을 확인할 수 있다.
- API 키를 브라우저에 저장하지 않는 경계를 명시했다.

남은 문제:

- 설정은 자주 보는 운영 대시보드가 아니라 초기 설정·장애 점검용이다. 기본 진입 화면이 아니라 별도 탭 또는 `/settings` 경로가 맞다.
- 실제 서비스에서는 공급자 등록 권한, 변경 이력, 연결 실패 알림도 필요하다.

### 3. Release workflow

현재 5단계 탭은 설명력은 있지만, 매번 운영자가 읽을 화면은 아니다.

권장 위치는 다음 중 하나다.

1. 운영 화면 상단의 작은 진행 표시줄: `AI 점검 → 사람 승인 → GIWA 증명 → 공개 검증`
2. `이 제품은 어떻게 작동하나요?` 도움말 패널 또는 온보딩
3. 피치덱과 팀 소개의 제품 설명 영역

상세 단계별 입력·출력·설명은 운영 화면의 주 콘텐츠가 아니라 필요할 때 여는 보조 정보여야 한다.

## 권장 정보 구조

```text
운영 화면 (기본)
  1. 현재 차단/공개 가능 상태
  2. 한 문장의 차단 이유와 책임자
  3. 지금 해야 할 단일 행동
  4. 선택 자산의 AI 근거와 문서 버전
  5. 짧은 진행 표시줄

승인 화면
  1. 변경된 문서와 AI 근거
  2. 검토자 확인 항목
  3. 지갑 승인
  4. GIWA 트랜잭션 결과

설정 화면
  1. 지갑·역할
  2. AI 공급자·모델·연결 상태
  3. 에이전트 권한과 실행 이력

공개 검증 화면 (공유 URL)
  1. 현재 공개 가능 여부
  2. 파일 해시 대조
  3. GIWA 이벤트·Explorer 링크
```

## 우선순위 권고

### P0 — 다음 데모 전

- 운영 화면에서 상세 Release workflow를 기본 노출하지 않는다.
- 대신 현재 단계만 보여 주는 4단계 진행 표시줄을 남긴다.
- 상단의 단일 행동 버튼이 실제 승인 또는 검증 단계로 연결되게 한다.

### P1 — 테스트넷 배포 후

- 승인 성공·실패, GIWA 트랜잭션 해시, Explorer 링크를 승인 흐름 안에 붙인다.
- 공시 가능 상태가 되면 공유 가능한 Passport URL/QR을 만든다.

### P2 — 실제 파일럿 전

- 지갑 역할별 권한 분리
- AI 공급자 변경 이력·연결 오류 알림
- 원문 근거 위치를 포함한 검토 화면

## 성공 기준

처음 방문한 운영자가 10초 안에 아래 세 질문에 답할 수 있어야 한다.

1. 어떤 자산의 공시가 막혔는가?
2. 왜 막혔는가?
3. 지금 누가 어떤 행동을 해야 하는가?

이 세 답이 한 화면에서 나오지 않으면 Asset Passport는 아직 신뢰 운영 도구가 아니라 설명이 많은 대시보드에 머문다.
