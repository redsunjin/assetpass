# 배포 전 제품 검증 기준

## 한 문장 목적

Asset Passport는 토큰이나 원본 문서를 보관하는 서비스가 아니라, 자산 운영 문서의 최신본·검토 책임·공시 상태를 누구나 같은 기준으로 확인하게 하는 증빙 도구다.

## 배포를 미루는 이유

현재 화면의 가상 데이터에는 이미 `공시 완료`인 자산이 있지만, 초기화 스크립트는 그 자산을 새로 등록한 뒤 검토 대기로 전환한다. 이 상태로 배포하면 화면의 설명과 실제 GIWA 상태가 어긋난다. 배포 뒤에는 화면을 온체인 이력과 연결해 같은 사실만 보여야 한다.

## 제품 경험의 기준

처음 보는 사람이 자산 하나를 열었을 때 1분 안에 아래 네 가지를 답할 수 있어야 한다.

1. 지금 최신 문서 버전은 무엇인가.
2. 누가 검토했고 승인 또는 반려했는가.
3. 지금 공시 가능한 상태인가.
4. 원본 문서와 개인정보는 체인에 기록하지 않았는가.

## 화면 전략

- 첫 화면: 서비스가 자산을 거래·보관하지 않고 운영 증빙만 다룬다는 경계를 한 문장으로 보여 준다.
- 자산 상세: 상태, 최신 버전, 마지막 검토자, 공시 여부, GIWA 트랜잭션 링크를 한 묶음으로 배치한다.
- 이력: `등록 → 문서 제출 → 검토 → 공시`를 시간순 타임라인으로 보여 준다.
- 데이터 경계: 원본 문서·실자산 보관 정보·투자자 개인정보는 기록하지 않는다고 별도 표시한다.
- 지갑 동작: 서명 전에는 행동의 의미와 대상 문서를, 서명 뒤에는 트랜잭션 해시와 결과 상태를 보여 준다.

## 시연 시나리오

### 1. 최신 문서 검토

발행자가 `demo-solar-001`의 문서 해시를 등록한다. 검토자가 지갑으로 승인한다. 발행자가 공시 상태로 전환한다. 검증자는 상세 화면과 GIWA Explorer에서 최신 버전·승인자·공시 상태가 일치함을 확인한다.

### 2. 잘못된 공개 방지

`demo-invoice-002`는 문서를 제출하지 않은 초안이다. 화면은 공시 불가 상태를 보여 주고, 컨트랙트는 승인 전 공시 전환을 거절한다. 이 장면은 상태 전이가 단순 표시가 아니라 규칙으로 막힌다는 증거다.

### 3. 원본 보호와 해시 검증

`demo-building-003`의 원본 문서는 공개하지 않는다. 제공된 샘플 문서의 SHA-256을 다시 계산해 화면·컨트랙트의 해시와 대조한다. 일치하면 문서가 바뀌지 않았음을, 불일치하면 검증 실패를 확인한다.

## 배포 통과 기준

- [ ] 화면의 자산 상태·문서 버전·날짜가 배포된 컨트랙트의 조회값과 일치한다.
- [ ] 등록, 검토 승인, 공시 전환의 트랜잭션 해시 3개가 GIWA Explorer에서 열린다.
- [ ] 승인 전 공시 시도가 컨트랙트에서 거절되는 것을 재현한다.
- [ ] 샘플 문서 해시를 독립적으로 다시 계산해 일치시킨다.
- [ ] 각 화면에서 원본 문서·실자산 보관·투자 권유를 하지 않는다는 경계를 확인한다.
- [ ] 제3자가 위 시나리오를 따라 1분 안에 최신 상태와 승인자를 찾는다.

## 배포 후 증빙 패키지

컨트랙트 주소, 트랜잭션 해시, Explorer 링크, 각 시나리오의 화면 캡처, 해시 대조 결과를 한 페이지에 기록한다. 이 페이지를 GASOK 제출 링크와 피치덱의 실제 검증 근거로 사용한다.
