AI가 공시 전 누락·버전 위험을 먼저 찾아내고, 사람이 승인한 공개 준비 상태만 GIWA에 증명합니다.

가상 자산으로 만든 작동 시연입니다. AI는 공시 위험과 다음 행동을 제안할 뿐, 법률 판단·자동 승인·자동 공시를 하지 않습니다. 최종 결정은 책임자의 지갑 승인으로만 이뤄지며 원본 문서는 GIWA에 기록하지 않습니다.

Release workflow

무엇이 어디서 판단되고, 무엇이 GIWA에 남는가

원본 문서는 밖에 두고, AI의 제안과 사람의 결정을 분리해 공개 준비 상태를 만듭니다.

  1. 01
    자료 등록

    발행자가 원본을 오프체인에 보관하고 문서 해시·버전만 등록합니다.

    입력: 문서 메타데이터
  2. 02
    AI 사전 점검

    공급된 LLM 또는 규칙 엔진이 버전·누락·승인 연결을 살펴봅니다.

    출력: 위험과 다음 행동
  3. 03
    사람의 승인

    검토자가 원문 근거를 확인하고 책임 있는 결정을 내립니다.

    행동: 지갑 서명
  4. 04
    GIWA 증명

    승인된 최신본의 해시·승인·상태 전이만 온체인에 기록합니다.

    증명: 트랜잭션 이벤트
  5. 05
    공개 검증

    파트너와 검증자가 파일 해시와 GIWA 이력을 직접 대조합니다.

    결과: 공유 가능한 Passport

현재는 내장 증빙 규칙이 선택되어 있습니다. 원본 파일은 전송하지 않고, 화면의 메타데이터·버전·승인 상태만 점검합니다.

로컬 LLM은 이 기기에서 실행 중인 Ollama에만 연결합니다. 외부 AI는 API 키를 브라우저에 넣지 않으며, 별도 보안 릴레이를 만든 뒤에만 활성화합니다.

01 · AI 제안

무엇이 빠졌는지 찾습니다

버전, 기준일, 필수 증빙, 이전 승인과의 연결을 비교해 위험과 다음 행동을 제안합니다.

02 · 사람의 결정

책임자가 승인합니다

AI는 승인권자가 아닙니다. 검토자와 감사자가 근거를 보고 지갑으로 결정합니다.

03 · GIWA 증명

공개 가능한 상태만 남깁니다

승인·상태 전이·문서 해시를 GIWA에서 대조해 외부 검증자가 확인합니다.
