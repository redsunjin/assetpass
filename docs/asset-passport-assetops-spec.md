# Asset Passport: AI 기반 온체인 자산운영 MVP

## 한 줄 정의

Asset Passport는 AI가 온체인 자산 상태를 정기 점검하고 거래안을 만들면, 사람이 지갑으로 승인한 거래만 정책 안에서 GIWA에 실행·증명하는 자산 운영 도구다.

이 MVP는 **풀 ERP나 수탁 서비스가 아니다.** 온체인 자금·토큰을 다루는 팀의 회계·재무 운영을 보조하는 `AssetOps` 승인 계층이다.

## 해결할 첫 문제

Web3 프로젝트, DAO, RWA 운영팀은 수수료 잔액 보충, 파트너 지급, 정산, 분배 같은 반복 거래를 수행한다. AI로 운영을 자동화하고 싶어도 AI에 개인키를 주면 안 된다. 수동 처리만 하면 잔액 부족·누락·정책 위반을 놓치기 쉽다.

첫 시연은 하나로 고정한다.

1. Asset Watcher가 운영 지갑의 Test ETH 잔액을 매일 점검한다.
2. 정책 기준보다 낮으면 Transaction Planner가 허용된 보충 지갑에 `0.001 Test ETH`를 보내는 안을 만든다.
3. Policy Guard가 수신자 화이트리스트와 건당 한도를 결정적으로 검사한다.
4. 운영자가 수신자·금액·근거를 보고 자신의 지갑으로 승인·실행한다.
5. Proof Keeper가 GIWA tx hash와 결과를 영수증으로 정리한다.

## 사용자와 시장 가설

초기 사용자는 온체인 자금·토큰을 실제 운영하는 Web3 프로젝트, DAO, RWA 발행/운영사의 재무·운영 담당자다. 구매자는 재무 책임자 또는 운영 책임자다.

확장 가설은 기업이 토큰화 자산, 온체인 정산, 지급·분배를 다루는 경우다. 다만 일반 기업의 모든 결재·회계 업무를 대체한다고 말하지 않는다. 온체인 자산 이동이 없는 일반 ERP는 체인이 아니라 기존 ERP·결재 도구가 더 적합하다.

## 역할 경계

| 주체 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| Asset Watcher | 잔액·예정 거래·미확정 tx를 주기적으로 점검 | 자산 이동 |
| Transaction Planner | 정책과 운영 데이터를 바탕으로 거래안·근거 작성 | 승인·서명 |
| Policy Guard | 허용 수신자·건당 한도·동일 제안 재실행을 결정적으로 검사 | 자연어 추론으로 정책 변경 |
| 사람의 지갑 | 내용을 확인하고 최종 거래를 서명 | AI에게 개인키 제공 |
| GIWA | 승인된 실제 자산 이동과 이벤트를 기록 | 원본 회계 자료·개인정보 보관 |
| Proof Keeper | 체인 결과를 대조하고 영수증 생성 | 거래를 재시도하거나 자동 전송 |

LLM은 여러 운영 정보를 읽기 쉽게 설명하고 거래안의 근거를 정리할 수 있다. 자금 통제는 LLM이 아니라 Policy Guard와 지갑 서명에 둔다.

## 왜 GIWA인가

체인을 쓰는 목적은 사람의 일반 워크플로를 투명하게 보이게 하는 것이 아니다. 승인 대상 자체가 온체인 자산 거래이기 때문이다.

- 사람의 지갑 서명, 실제 자산 이동, 실행 이벤트가 동일한 체인에서 대조된다.
- AI가 제안한 내용과 정책 해시를 실행 이벤트에 묶어 사후 대조할 수 있다.
- 팀 외부의 감사자·파트너도 애플리케이션 DB를 믿지 않고 tx hash로 결과를 확인할 수 있다.

GIWA Test ETH는 이 MVP에서 테스트 거래와 수수료를 위한 네이티브 자산일 뿐이며, 별도 토큰을 발행하지 않는다.

## MVP 기능과 비범위

포함:

- 지갑 잔액 기준과 지급 일정의 점검 결과
- AI 에이전트의 거래 제안, 근거, 위험 설명
- 허용 수신자·건당 한도 정책 검사
- 지갑 소유자의 승인 뒤 실행되는 Test ETH 거래
- 제안 해시·정책 해시·승인자·수신자·금액·tx hash 영수증

제외:

- 개인키 보관, AI 자동 실행, 무인 자금 운용
- 법정화폐 장부, 세금, 인보이스, 급여, ERP 전체 기능
- 실제 자금·실물자산 수탁, 투자 권유, 수익 보장
- 법률·회계·투자 적합성의 자동 판단

## 구현 단계

1. **P0 사용자 여정:** 화면은 `테스트넷 준비 필요 → 설정 필요 → 승인 대기 → 실행 완료` 상태 중 하나만 주 행동으로 제시한다. 미배포 상태에서는 실행 버튼을 노출하지 않는다.
2. **P1 테스트넷:** `AssetPassportController` 배포·자금 예치, 연결 지갑이 허용 거래를 실제 실행, Explorer 영수증 표시.
3. **P2 에이전트 서비스:** 서버 스케줄러가 Watcher를 실행하고, AI 결과와 정책 스냅샷을 제안 레코드로 보관.
4. **P3 산업 확장:** RWA 분배·정산, DAO 운영비, 기업 온체인 지급에 맞는 정책 템플릿과 다중 승인 연동.

## 완료 기준

동일한 proposal ID에 대해 `감시 결과 → 정책 검사 → 사람의 지갑 실행 → GIWA tx → 영수증`이 끊기지 않고 연결되면, 이 MVP의 핵심 약속을 증명한 것이다.

P0에서 확인할 것은 기능 수가 아니라 인지다. 첫 방문자가 현재 상태와 다음 한 행동을 10초 안에 말할 수 있어야 한다. 이 상태 전이는 `scripts/journey-state-test.mjs`로 계속 검사한다.
