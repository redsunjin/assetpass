# 공개 표면 품질·정합성 점검

점검일: 2026-07-31  
대상: 팀 소개(`/`), 피치덱, MVP(`/mvp/`), README와 GASOK 브리프, 공개된 과거 자료

## 판정

제품의 한 문장과 핵심 증거는 이제 같은 방향을 가리킨다.

> AI가 거래안을 만들고, Controller owner 지갑이 승인한 거래만 GIWA에서 실행한다.

다만 MVP는 초기 단계다. Test ETH E2E는 CLI 테스트 지갑으로 끝났고, 공개 MVP의 owner 브라우저 지갑 검증과 실제 주기적 Watcher 서비스는 남아 있다. 이 경계를 모든 공개 표면에 같은 문장으로 표시했다.

## 공통 기준

1. 첫 화면 10초 안에 사용자·문제·다음 행동을 알 수 있는가.
2. 구현하지 않은 범위와 실제 검증한 범위를 구분하는가.
3. AI·정책·지갑·GIWA의 권한이 섞이지 않는가.
4. 팀 소개, 피치덱, MVP, README가 같은 제품을 설명하는가.

## 발견 사항과 조치

| Before | After | Why |
| --- | --- | --- |
| 팀 소개와 피치덱이 Test ETH E2E를 ‘다음 검증’으로 표기 | Controller 배포·정책 등록·0.002 예치·0.001 실행·중복 차단 완료와 브라우저 검증 잔여를 분리 표기 | 이미 검증한 사실을 숨기거나, 아직 하지 않은 브라우저 검증을 완료처럼 보이면 신뢰가 깨진다. |
| 피치덱에 초기 사용자가 보이지 않음 | Web3·DAO·RWA 운영팀의 재무·운영 담당자로 명시 | 범용 ERP처럼 보이면 체인을 쓰는 이유와 첫 고객이 흐려진다. |
| MVP가 ‘연결한 지갑 소유자’가 실행한다고 표시 | Controller owner 지갑만 정책 등록·결제를 실행한다고 표시하고, 연결 계정과 owner를 온체인 조회 | 컨트랙트의 `onlyOwner` 제한과 화면 권한을 일치시킨다. |
| 기본 거래안이 이미 실행된 proposal ID여서 재실행 시 실패 | 다음 수동 브라우저 점검용 새 proposal ID로 전환 | 중복 실행 차단은 정상 동작이지만, 데모가 이유 없이 실패한 것처럼 보여서는 안 된다. |
| 모바일 진행 레일이 가로 스크롤에 의존 | 작은 화면에서는 단계가 세로로 모두 보이게 변경 | 워크플로 인지가 제품의 핵심이므로 손가락으로 옆으로 밀어야 하는 구조를 피한다. |
| 공개된 Release Gate 도식·서비스 정의가 현 제품처럼 보임 | 피벗 전 가설이라는 아카이브 고지와 현재 MVP 링크를 추가 | 이전 RWA 문서 제품과 현재 AssetOps 제품이 충돌하지 않게 한다. |
| GASOK 브리프가 문서 공시·Registry 중심 | AssetOps 제안·정책·사람 승인·GIWA 실행 중심으로 현행화 | 발표 자료와 실제 컨트랙트의 행동을 맞춘다. |

## 화면별 결과

### 팀 소개

- 역할: 제품의 문제, 현재 증거, 데모·피치덱 진입점.
- 수정: 중복된 두 데모 카드를 MVP와 피치덱으로 나누고, Test ETH 영수증 링크를 추가했다.
- 남은 점검: 실제 팀/고객 인터뷰 근거가 생기면 시장성 문장을 그 근거로 보강한다.

### 피치덱

- 역할: 특정 초기 사용자와 체인 사용 이유를 짧게 설득.
- 수정: ‘다음 테스트넷 검증’을 완료된 CLI E2E와 남은 브라우저 검증으로 나눴다.
- 남은 점검: 발표 전 3분 리허설에서 슬라이드 6의 Explorer 영수증 링크와 MVP 상태를 함께 확인한다.

### MVP

- 역할: 한 건의 거래를 사람이 통제하는 과정을 보여 주고, owner 아닌 지갑에는 실행을 열지 않음.
- 수정: Controller의 `owner()`를 조회해 비승인 지갑은 계정 전환만 안내하고, 정책 등록·결제를 호출하지 않게 했다.
- 남은 점검: owner 브라우저 지갑에서 새 proposal로 정책 조회 → 실행 → Explorer 영수증까지 수동 검증한다.

### 문서와 과거 자료

- 역할: README와 GASOK 브리프는 현재 제품 정의의 기준 문서, Release Gate 자료는 사고 과정의 아카이브.
- 수정: README·GASOK 브리프·실행 보드를 AssetOps E2E 상태로 고쳤고, 과거 공개 도식과 서비스 정의에는 아카이브 고지를 넣었다.

## 현재 공개 약속

- AI는 점검·제안·설명만 하며 개인키와 자동 송금 권한이 없다.
- Policy Guard가 실제로 검사하는 범위는 허용 수신자, 건당 한도, 동일 거래안 재실행 방지다.
- Controller owner 지갑만 정책 등록과 결제를 실행한다.
- GIWA Sepolia에서 Test ETH E2E 1건을 CLI 테스트 지갑으로 확인했다.
- 브라우저 지갑 E2E와 서버 기반 주기적 Watcher는 아직 완료하지 않았다.

## 다음 품질 게이트

1. owner 브라우저 지갑으로 새 proposal을 실행해 MVP 화면과 Explorer 영수증이 같은 거래를 가리키는지 확인한다.
2. 390px 모바일에서 진행 레일·온보딩·권한 안내를 수동 점검한다.
3. 3분 발표 리허설에서 팀 소개 → 피치덱 → MVP → Explorer를 한 흐름으로 점검한다.

이 세 항목이 끝나면 ‘기능을 많이 보여 주는 데모’가 아니라, 주장과 증거가 맞물린 제출용 MVP로 판단할 수 있다.
