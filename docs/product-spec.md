# 아카이브 — 제품 명세 v0.1

> 이 문서는 피벗 전 RWA Release Gate 제품 명세다. 현재 구현·발표 기준은 [AssetOps 제품 명세](asset-passport-assetops-spec.md)다.

## 사용자와 역할

| 역할 | 하는 일 | MVP 권한 |
|---|---|---|
| AI Release Copilot | 버전·누락·승인 연결의 위험과 다음 행동을 제안 | 읽기 전용 분석, 승인권 없음 |
| 발행자 | 자산과 문서 버전을 등록 | 등록·갱신 요청 |
| 검토자 | 문서와 상태 변경을 검토 | 승인·반려 서명 |
| 감사자 | 이력과 증빙을 확인 | 읽기 전용·검토 서명 |
| 검증자 | 최신 상태를 확인 | 공개 읽기 전용 |

## 핵심 사용자 흐름

```text
자산 등록 → 문서 업로드/해시 생성 → AI 사전 점검(위험·다음 행동 제안)
→ 검토자 지갑 승인 → GIWA Asset Registry에 공개 준비 상태 기록 → 공개 검증 화면에서 최신 상태 확인

## 관리자 운영 콘솔

관리자는 공개 진행을 한 화면에서 다음 네 단계로 확인한다.

1. **AI 사전 점검** — 내장 증빙 규칙 또는 사용자가 실행한 로컬 Ollama가 버전·누락·승인 연결을 점검한다.
2. **책임자 승인** — 연결된 EVM 지갑과 GIWA Sepolia 네트워크 상태를 확인한 뒤, 책임자가 승인한다.
3. **GIWA 공개 증명** — 사람의 승인 뒤에만 해시·승인·상태 전이를 기록한다.
4. **외부 검증** — 검증자가 파일 SHA-256과 온체인 이벤트를 대조한다.

AI 설정은 브라우저의 로컬 저장소에만 남긴다. 기본값은 네트워크 호출이 없는 내장 증빙 규칙 엔진이다. 선택적으로 `localhost`/`127.0.0.1`의 Ollama에만 문서 원본 없이 메타데이터를 보내 사전점검 초안을 만들 수 있다. 외부 제공형 AI는 API 키를 브라우저에 저장하지 않으며, 개인정보·비밀키 보호를 위한 서버 측 보안 릴레이가 준비되기 전까지 비활성화한다.
```

## 데이터 모델

- `Asset`: ID, 이름, 자산 유형, 설명, 발행 주체(데모), 상태, 공시 예정일
- `DocumentVersion`: 자산 ID, 문서 종류, 버전, SHA-256, 업로드 시각, 상태
- `Attestation`: 대상 ID, 역할, 지갑 주소, 결정, 서명/트랜잭션 ID, 시각
- `DisclosureEvent`: 자산 ID, 제목, 기한, 상태, 연결 문서 버전
- `AuditEvent`: 행위, 주체, 대상, 이전/이후 상태, 시각
- `AIReleaseBrief` (오프체인): 탐지 신호, 근거 위치, 위험 설명, 제안 행동. AI 결과만으로 상태를 변경할 수 없다.

## GIWA 온체인 범위

Asset Registry는 최소 데이터만 저장한다.

- `assetId`와 현재 상태
- 최신 문서 해시 및 버전
- 상태 변경과 승인자의 주소·시각

원본 문서, 개인식별정보, 금액, 투자자 목록은 체인에 기록하지 않는다.

AI는 법률 자문, 투자 적합성 판정, 자동 승인, 자동 공시를 하지 않는다. 최종 결정과 상태 전이는 역할을 가진 사람이 지갑으로 서명한 뒤에만 발생한다.

## 성공 기준

- GIWA 테스트넷에서 3개 가상 자산을 등록할 수 있다.
- 문서 버전 변경과 검토자 승인 이력이 트랜잭션으로 확인된다.
- 별도 계정 없이 검증 화면에서 자산 상태와 최신 증빙을 확인할 수 있다.
- 모든 화면에 `데모용 가상 자산 / 금융상품 아님` 고지가 보인다.
- AI가 최신 문서와 기존 승인 이력의 불일치를 찾아 공시를 차단하는 장면을 시연한다.
- 사람의 승인 뒤에만 공시 전환이 가능하고, 외부 검증자가 파일 해시와 체인 이력을 대조할 수 있다.
